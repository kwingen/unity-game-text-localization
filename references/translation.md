# 翻译与质量校验

## 1. 提供方选择

| 方式 | 适用场景 | 注意 |
|---|---|---|
| 人工翻译 | 高质量、小批量、关键剧情 | 成本高，需结构校验 |
| 本地模型 | 离线、隐私敏感、大批量 | 需测速和质量，仍要 QA |
| 在线模型 | 用户明确许可且内容不敏感 | 不要泄露未授权文本 |
| 翻译记忆 | 已有官方/历史译文 | 优先复用，标记来源 |
| 规则/词典 | 菜单、短标签、术语 | 适合辅助而非主翻译 |

选择前确认：源语言、目标语言、语域、人名策略、标点规范、长度限制。

## 2. 术语表

- 按最长匹配优先。
- 记录词性、上下文、禁止译法和别名。
- 人名、地名、系统名、UI 标签要单独维护。
- 术语表变更时记录版本号；已有译文需按影响范围重跑或标记。

## 3. 模型请求约束

如果使用模型翻译：

- 输出只包含译文，不包含解释。
- 逐条或小批量请求，避免上下文串扰。
- 明确要求保留占位符、标签、换行和顺序。
- 设置合理重试次数和截断检测。
- 对长文本拆段时，先保护占位符再翻译。
- 不要让模型接触无关文件或密钥。

## 4. 结构校验

每条译文至少检查：

- 占位符多重集和顺序
- 换行数量与行序
- 富文本标签闭合
- 参数名和格式化 token
- 目标语言字符集
- UI 长度和行数
- 术语一致性
- 原文回显、代码块、JSON 包裹、解释性前缀
- 空译文、重复译文、明显机翻错误

## 5. 质量审计

输出 `qa-report.json`：

```json
{
  "total": 0,
  "translated": 0,
  "failed": 0,
  "curated": 0,
  "placeholder_errors": 0,
  "length_errors": 0,
  "glossary_errors": 0,
  "coverage_by_source": {},
  "unresolved": []
}
```

失败条目按类型处理：

- 结构错误：修复或重译
- 术语漂移：更新术语表后重跑受影响子集
- 长度超限：改写或调整 UI
- 短标签歧义：人工确认
- 模型反复截断：停止重试，转人工或拆段

## 6. 翻译记忆与复用

- 保存原文、译文、来源、版本、上下文。
- 优先复用官方目标语言文本。
- 相同原文在不同上下文可有多译文，不要盲目覆盖。
- 游戏更新后按语料 ID 做增量合并。
