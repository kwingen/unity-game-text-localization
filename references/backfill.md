# 回填、字体与打包

## 1. 策略决策

1. 游戏已有本地化系统 → 新增 locale 或改表。
2. 文本在外部数据文件 → 字段级数据补丁。
3. 文本在序列化资产 → asset overlay。
4. 文本在代码或运行时生成 → Hook 显示或本地化入口。
5. 文本在图片/音视频 → 单独媒体工作流。

不要为了统一方案把所有文本都塞进运行时字典；能安全离线回填的优先离线。

## 2. 资产补丁

- 只读原资源，输出到独立 overlay。
- 每个改动位置先验证原文匹配，再写入译文。
- 写后重新读回并做结构校验。
- 未修改对象保持原字节一致。
- 记录 source/patched SHA256、对象数、字段路径。
- 处理 AssetBundle 依赖、catalog、压缩和 Unity 版本一致性。

## 3. 运行时 Hook

- 常见方案：BepInEx、MelonLoader、Harmony。
- 优先 Hook：
  - 本地化查询函数
  - UI `SetText` / text setter
  - 字符串格式化后的最终显示点
- 避免盲目 Hook 所有字符串比较函数。
- 字典使用精确匹配；如需模糊匹配，必须记录规则和风险。
- 保留原字符串，不做不可逆替换。
- Hook 要处理异常，失败时回退原文本。

## 4. 字体与 UI

- 识别 UGUI Font、TMP_FontAsset、自定义字体系统。
- 目标字体必须覆盖译文全部字符。
- TMP 需考虑动态字体、SDF atlas、fallback 字体。
- UI 检查：溢出、换行、字距、行高、自动缩放、粗斜体。
- 若替换字体，尽量保持原视觉风格；不要默认使用系统字体。

## 5. 打包

交付结构建议：

```text
dist/
|-- overlay/
|-- loader/          # 可选
|-- fonts/           # 可选
|-- patch-manifest.json
|-- install.md
`-- rollback.md
```

清单必须记录：

- 游戏构建哈希或版本
- Unity 版本
- 每个改动文件与对象
- 回滚方式
- 已知兼容性限制

## 6. 验证

- 在隔离副本部署，不直接改原目录。
- 对比部署前后关键文件哈希。
- 启动游戏，收集日志、截图或取证数据。
- 验证关键文本、字体、UI 布局和占位符。
- 记录未验证场景，不用“已完成全部汉化”这类绝对表述。
