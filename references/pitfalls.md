# 踩坑记录

## 1. 模型选择：规划强 vs 内容过滤

**现象**：强推理模型（如 gpt-6-astra）在规划任务、分析游戏结构、编写提取代码、梳理管线方面效果好；但目标游戏是成人内容时，**在线模型频繁触发内容过滤**：拒绝翻译、中断对话、拒绝读取含敏感文本的资源。

**对策**：
- **任务分工**：结构分析、脚本编写、管线设计、校验逻辑用在线强推理模型；**正文翻译一律本地 Sakura**（无过滤、可离线、可控成本）。
- 提取阶段若模型拒绝读取资源内容，让它只分析结构/写代码，由本地脚本直接产出语料，模型不接触原始敏感文本。
- 成人内容自动化只针对用户明确授权的目标，不把特定作品信息写成通用规则。

## 2. Sakura 翻译问题

### 2.1 术语表子串污染
短词会匹配进长词内部：`ロード→读取` 使 `ダウンロード` 被拆成 `ダウン[读取]` → 译文变成「读取中/下载读取」；`プリロード/リロード` 同样被污染，甚至导致校验失败。
**对策**：术语按最长优先匹配；含短词的常见长词显式入表（`ダウンロード→下载`、`プリロード→预加载`、`リロード→重新加载`）。改表会改变 `glossary_sha256`，旧断点全部失效——改表前规划重跑范围。

### 2.2 模型「话痨」：生成满预算不收敛
部分剧情/涩涩长句（大量 `♡`、`/` 分隔、省略号）触发无限生成，打满 max_tokens（如 1024）仍无 EOS → 判 truncated（finish_reason != stop）。单次 90s+，重试 3 次约 5 分钟，**几乎必然失败**。
**对策**：识别特征后不盲目重试；直接人工/Agent 收尾，或先拆成更小纯文本段；批量前先探测，单槽排队时一个话痨请求阻塞后续全部。

### 2.3 prompt 泄漏
模型偶发把「将下面的日文文本翻译成中文：」整句回显进译文。校验显式拒绝该特征串与任何代码块/JSON 包裹。

### 2.4 降级路径丢术语
segment fallback 逐段重译时，名称/术语（如 `イメルタ→伊梅尔塔`）可能被改写或漏掉 → 「fallback changed glossary identity/order/multiplicity」。
**对策**：fallback 段重译后校验术语身份/顺序/多重性；失败即人工收尾，不无限重试。

### 2.5 服务器性能与排队
`--parallel 1` 单槽：一个慢请求阻塞全部。测速用真实请求、算排队；先看服务端日志（token 速率、finish_reason、n_gen）再下结论，别归咎模型限速或网络。

## 3. 收尾策略：最后十几条人工收尾

**现象**：全量跑完后剩余 10~20 条顽固失败（话痨截断、短串边界如 `オン`/`さん`/`トグルテキスト`、术语降级丢失）。继续用 Sakura 重试 → 每条 3×90s+，成功率极低，浪费 GPU 时间与 token。

**对策**：
- 全量后**不要**对失败清单整批重试；先按错误类型分类：可修复（术语污染 → 改表重跑子集）与注定失败（话痨/短串/降级丢术语 → 校订）。
- 校订（curated）译文照旧做结构校验（标签/占位符/行数/分隔符原样保留），记录来源标记。
- 条数少时，模型单次调用成本（时间/token）远高于人工校订成本。

## 4. 字体：风格与适配

### 4.1 先识别原字体风格
查原 TMP_FontAsset 名称（如 `Stick-Regular SDF_low` = 丸ゴシック，圆润）与 UGUI 字体，选对应中文风格：
- 丸ゴシック/圆润 → 中文圆体（如 **幼圆 YouYuan**）
- 黑体/哥特 → 思源黑体/微软雅黑
- 不要默认雅黑——风格不匹配会很明显。

### 4.2 覆盖率预检（防 □）
替换前用 GDI `GetGlyphIndicesW` 对**全部译文去重字符**做缺字检测（含 CJK/假名/全角）。缺字处理：
- 首选换候选字体；
- 次选字符级规范化：如片假名中点 `・`(U+30FB) → 中文间隔号 `·`(U+00B7)（多数圆体有后者，且更符合中文规范）；
- 保留通用兜底字体做二级 fallback（如 ARIALUNI），覆盖生僻字。

### 4.3 TMP 运行时字体创建（大坑）
BepInEx 插件运行时创建 TMP 字体：
- `TMP_FontAsset.CreateFontAsset(Font, ...)` 8 参重载 → **Player 运行时返回 null**；
- `AtlasPopulationMode.DynamicOS` → **同样返回 null**；
- **三参 `CreateFontAsset(familyName, styleName, pointSize)` 可用**（按 OS 字体名创建动态 SDF）。
- 实现多路径回退并逐路径打日志，避免静默失败。
- 类型位置：`GlyphRenderMode` 在 `UnityEngine.TextCoreModule`（`UnityEngine.TextCore.LowLevel.GlyphRenderMode`，`SDFAA` 可用）；`AtlasPopulationMode` 在 `Unity.TextMeshPro`（Dynamic=1, DynamicOS=2）。
- 主字体原样保留（fallback 模式），中文走圆体，原日文字形不受影响。

### 4.4 验证
BepInEx 日志确认「UGUI font loaded: <字体>」「TMP rounded font loaded」+ **0 缺字/错误**；取证 + 截图人工确认风格。

## 5. 其他流程坑

- **PIN/密码锁屏**：部分作品启动后锁屏，阻塞视觉/点击验收。不尝试破解密码界面；改做「启动冒烟 + 日志 + 取证」验证，锁屏操作交给用户。
- **验收语言**：冒烟通过 ≠ 全流程通关。交付状态写 `pending_full_playthrough`，不夸大成「已完成汉化」。
- **隔离副本一致性**：覆盖前核对隔离副本资产与补丁基线哈希等价（可回滚）；先关游戏进程再替换 DLL；覆盖后逐文件 SHA256 校验。
- **会话/UI 状态**：任务已完成但界面仍显示「运行中」时，先查数据库/API 状态与残留进程，再判断是缓存问题还是真在跑；有 `stopRun` 类端点可幂等调用确认。
